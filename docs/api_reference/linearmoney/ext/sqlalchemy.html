 19class VectorMoney(TypeDecorator):
 20    """SQLAlchemy column type that automatically serializes and
 21    deserializes a `linearmoney.vector.MoneyVector` to and from a String column
 22    for storage in the db.
 23
 24    This type preserves all vector information including the currency space, so
 25    it should be used whenever non-destructive storage is desired.
 26
 27    The disadvantage of this column type is that it uses a sqlalchemy String column
 28    (VARCHAR) underneath, so in-db aggregate functions like SUM and MAX cannot
 29    be used and these operations need to be performed in Python if they are needed.
 30
 31    Another consequence of this is that comparisons in where clauses don't work as
 32    expected. For example,
 33    `select(VectorModel).where(VectorModel.money_column > money_vector)` will compare
 34    the serialized string of `money_vector` against the string stored in the db for the
 35    greater than operator, so it will not give a correct result based on the actual
 36    monetary values of the vectors.
 37

 39        >>> from sqlalchemy.orm import Mapped, mapped_column, DeclarativeBase
 40        >>>

 48        ...

 85class AtomicMoney(TypeDecorator):
 86    """SQLAlchemy column type that automatically serializes and
 87    deserializes a `linearmoney.vector.MoneyVector` as an atomic value in the smallest
 88    denomination of `currency` to and from an integer column for storage in the db.
 89
 90    This type is intended to be used with single-currency applications. It
 91    evaluates the stored asset vector in a single-currency space defined by
 92    the `currency` argument provided on column declaration.
 93
 94    This means that attempting to store a money vector from a different currency space
 95    will result in a `linearmoney.exceptions.SpaceError`.
 96
 97    The reason for using a single-currency space in the internal calculations instead
 98    of checking the space of the passed in vector is to ensure that
 99    the value read from the database is the same value that was written to it.
100
101    For example, if we store a vector of (0 EUR, 10 USD,) in an AtomicMoney column
102    for USD, then it will store the integer 1000 in the database. We will get the
103    same value stored if we store a vector of (10 USD,). The difference is that
104    we lose the information about the currency space when storing the value as an
105    integer, so when we read the values from the db, both with deserialize to (10 USD,).
106    By enforcing a single-currency space on write, we ensure that the values read
107    from the database are actually the values that were written to the database, and
108    we ensure that the integrity of math on those values will not be compromised
109    through any subsequent writes/reads to/from the database.
110
111    The main advantage of this column type is that it allows the use of in-db aggregate
112    functions like SUM and MAX as well as ordered comparisons. The disadvantage is
113    that it can only be used with single-currency applications or with a manual
114    conversion step before passing any values into sqlalchemy's column operations.
115    For this reason, multi-currency applications should generally choose `VectorMoney`
116    instead.
117
118    Examples:
119        >>> from sqlalchemy.orm import Mapped, mapped_column, DeclarativeBase
120        >>>
121        >>> import linearmoney as lm
122        >>> from linearmoney.ext.sqlalchemy import AtomicMoney
123        >>>
124        >>> class BaseModel(DeclarativeBase): ...
125        >>>
126        >>> CURRENCY = lm.data.currency("USD")
127        >>>
128        >>> class LMExample(BaseModel):
129        ...
130        ...     __tablename__ = "lm_example"
131        ...
132        ...     id: Mapped[int] = mapped_column(primary_key=True)
133        ...     money_column: Mapped[AtomicMoney] = mapped_column(AtomicMoney(CURRENCY))
134    """
